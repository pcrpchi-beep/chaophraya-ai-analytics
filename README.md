# 🌊 ChaoPhraya AI Water Monitor

ระบบเว็บแอปพลิเคชันวิเคราะห์และพยากรณ์ระดับน้ำในแม่น้ำเจ้าพระยาด้วยปัญญาประดิษฐ์
(โปรเจควิชา หลักการนำแบบจำลอง AI ไปใช้ในระบบวิเคราะห์ข้อมูล)

- **ข้อมูล:** ผังน้ำลุ่มเจ้าพระยา สถาบันสารสนเทศทรัพยากรน้ำ (สสน.)
  https://tiwrm.hii.or.th/DATA/REPORT/php/chart/chaopraya/small/chaopraya.php
- **สถิติ:** การเปลี่ยนแปลงรายวัน, MA7, MA30, Volatility, ระยะห่างจากตลิ่ง, % ความจุลำน้ำ
- **Machine Learning:** พยากรณ์ระดับน้ำล่วงหน้า 1–3 วัน เปรียบเทียบ Ridge Regression, Random Forest, Gradient Boosting กับ Baseline แล้วเลือกโมเดลที่ดีที่สุดของแต่ละสถานี
- **Generative AI:** Gemini อธิบายผลเป็นภาษาไทย
- **Deploy:** GitHub + Streamlit Community Cloud, Login ด้วย Firebase

## ระบบปัญญาประดิษฐ์

**1. ข้อมูล** — หน้าเว็บผังน้ำของ สสน. ฝังข้อมูลไว้ในตัวแปร JavaScript `json_data`
`water_service.py` ส่ง POST `datepicker=YYYY-MM-DD` ไปที่หน้าเว็บ แล้วดึงส่วน `tele` (สถานีโทรมาตร สสน.) และ `itc_water` (สถานีกรมชลประทาน C2, C13 ที่มีปริมาณน้ำไหลผ่าน) ออกมา
ข้อมูลย้อนหลัง 2 ปีเก็บไว้ใน `data/history.csv` ตอนเปิดเว็บ ระบบจะดึงเฉพาะวันที่ขาดจากเว็บมาเติม

**2. สถิติ** (`stats_service.py`) — การเปลี่ยนแปลงรายวัน, MA7, MA30, Volatility (SD ของการเปลี่ยนแปลงรายวัน), ระยะห่างจากตลิ่ง, % ความจุลำน้ำ และระดับสถานการณ์ตามเกณฑ์ สสน.

**3. Machine Learning** (`ml_service.py`)
- **Target:** ระดับน้ำที่จะเปลี่ยนไปใน 1, 2, 3 วัน (ทำนายส่วนต่าง แล้วบวกกับระดับน้ำวันนี้)
- **Features:** การเปลี่ยนแปลงของระดับน้ำสถานีนั้นย้อนหลัง 1/2/3/7 วัน, ระยะห่างจากค่าเฉลี่ย 7 วัน, การเปลี่ยนแปลงของสถานีต้นน้ำทุกสถานี และการเปลี่ยนแปลงของปริมาณน้ำไหลผ่าน C2/C13
  (ไม่ใช้ค่าระดับน้ำสัมบูรณ์ เพราะทดลองแล้วทำให้โมเดลแบบต้นไม้ทำนายผิดมากเมื่อเจอระดับน้ำที่ไม่เคยเห็น)
- **โมเดลที่เปรียบเทียบ:** Persistence (Baseline: พรุ่งนี้เท่ากับวันนี้), Ridge Regression, Random Forest, Gradient Boosting
- **การแบ่งข้อมูล:** ตามเวลา ไม่สุ่ม — Train 80% แรก, Test 20% ล่าสุด (มิ.ย.–ต.ค. 2569 ช่วงน้ำหลาก)
- **การเลือกโมเดล:** Time-Series Cross-Validation 4 รอบบนชุด Train แล้วเลือก MAE เฉลี่ยต่ำสุด
- **ช่วงความไม่แน่นอน:** เปอร์เซ็นไทล์ที่ 10–90 ของความคลาดเคลื่อนบนชุด Test

ผลบนชุด Test (MAE เฉลี่ย 8 สถานี หน่วยเมตร):

| ล่วงหน้า | Baseline | Ridge | Random Forest | Gradient Boosting | โมเดลที่เลือก |
|---|---|---|---|---|---|
| 1 วัน | 0.206 | 0.128 | 0.137 | 0.135 | 0.129 |
| 2 วัน | 0.371 | 0.242 | 0.258 | 0.254 | 0.242 |
| 3 วัน | 0.523 | 0.367 | 0.386 | 0.376 | 0.370 |

โมเดลลดความคลาดเคลื่อนลงประมาณ 30–37% เทียบกับ Baseline (ผลรายสถานีอยู่ใน `model/metrics.csv`)
ข้อสังเกต: สถานี CPY014 (นนทบุรี) ได้รับอิทธิพลน้ำทะเลขึ้นลง โมเดลยังทำได้ไม่ดีกว่า Baseline
และ PIN005 ไม่มีสถานีต้นน้ำในชุดข้อมูล ระบบจึงเลือก Baseline ให้

**4. Generative AI** (`ai_service.py`) — ส่งสถิติ ผลพยากรณ์ และสถานะทุกสถานีเป็น JSON ให้ Gemini อธิบายเป็นภาษาไทย โดยกำหนดให้ใช้เฉพาะตัวเลขที่ส่งไป

**ข้อจำกัด** — ข้อมูลรายวัน 2 ปีเท่านั้น, ไม่มีข้อมูลฝนและแผนการระบายน้ำของเขื่อน, เหตุการณ์ผิดปกติ (พายุ/เปลี่ยนแผนระบายน้ำ) อาจทำให้ผลพยากรณ์คลาดเคลื่อน

## ขั้นตอนติดตั้ง (VS Code)

1. แตกไฟล์ แล้วเปิดโฟลเดอร์ `chaophraya-ai` ใน VS Code
2. เปิด Terminal แล้วติดตั้งไลบรารี
   ```
   pip install -r requirements.txt
   ```
3. คัดลอก `.env.example` เป็น `.env` แล้วใส่ `GEMINI_API_KEY`
   (ขอได้ฟรีที่ https://aistudio.google.com/apikey)
   ถ้ายังไม่ทำ Firebase ให้ลบบรรทัด `FIREBASE_API_KEY` ออก ระบบจะเข้าใช้งานได้เลยโดยไม่ต้อง Login
4. รันเว็บ
   ```
   streamlit run app.py
   ```
5. (ไม่บังคับ) อัปเดตข้อมูลและเทรนโมเดลใหม่ (ใช้เวลาประมาณ 1–2 นาที)
   ```
   python train_model.py --update
   ```

### แก้ปัญหาที่พบบ่อย
- **ขึ้นว่าดึงข้อมูลสดไม่สำเร็จ** — เว็บ สสน. ล่มหรือเน็ตหลุด ระบบจะใช้ `data/history.csv` แทน ใช้งานต่อได้
- **เปิดเว็บครั้งแรกช้า** — ถ้าเวอร์ชัน scikit-learn ไม่ตรงกับไฟล์โมเดล ระบบจะเทรนใหม่อัตโนมัติ (ประมาณ 1–2 นาที) หรือรัน `python train_model.py` ในเครื่องแล้วอัปโหลด `model/` ใหม่
- **AI ไม่ตอบ** — ตรวจ `GEMINI_API_KEY` และชื่อ `GEMINI_MODEL`

## นำขึ้น GitHub และ Deploy

1. สร้าง Repository ใหม่ เช่น `chaophraya-ai` แล้วอัปโหลดทุกไฟล์ **ยกเว้น `.env`**
   (ต้องมี app.py, *_service.py, requirements.txt, data/, model/)
2. ไปที่ https://share.streamlit.io → Create app → Deploy a public app from GitHub
3. เลือก Repository, Branch `main`, Main file `app.py`
4. Advanced settings → Secrets ใส่
   ```toml
   GEMINI_API_KEY = "..."
   GEMINI_MODEL = "gemini-3.6-flash"
   FIREBASE_API_KEY = "..."
   ```
5. กด Deploy

## ระบบ Login ด้วย Firebase

1. https://console.firebase.google.com → Create a project
2. Security → Authentication → Get started → เปิด Email/Password
3. Settings → General → Your apps → กดไอคอน `</>` ลงทะเบียน Web app
4. คัดลอก `apiKey` ไปใส่เป็น `FIREBASE_API_KEY` ใน Streamlit Secrets (และ `.env`)

## คู่มือการใช้งาน

1. **เข้าสู่ระบบ** สมัครที่แท็บ "สมัครสมาชิก" แล้ว Login ด้วย Email/Password
2. **แถบด้านซ้าย** เลือกสถานี, ช่วงเวลา (7/30/90/365 วัน), กด "ดึงข้อมูลล่าสุด" หรือ Logout
3. **ภาพรวม** การ์ดสถานการณ์ทุกสถานีตลอดลำน้ำ, ตัวเลขสำคัญของสถานีที่เลือก, กราฟระดับน้ำเทียบตลิ่งพร้อมเส้นพยากรณ์
4. **ข้อมูลระดับน้ำ** ตารางรายวันและปุ่มดาวน์โหลด CSV
5. **วิเคราะห์สถิติ** MA7, MA30, Volatility, ค่าสูงสุด/ต่ำสุด, กราฟการเปลี่ยนแปลงรายวัน
6. **พยากรณ์ (ML)** ค่าพยากรณ์ 1–3 วันพร้อมช่วงความไม่แน่นอน, ตารางประสิทธิภาพโมเดล, กราฟปัจจัยสำคัญ
7. **AI Insights** กดปุ่ม แนวโน้ม / ความเสี่ยง / สรุปภาพรวม หรือพิมพ์คำถามเอง แล้วกด Analyze

### เกณฑ์ระดับน้ำ (ตามผังน้ำ สสน.)
% ความจุลำน้ำ = (ระดับน้ำ − ระดับท้องน้ำ) ÷ (ระดับตลิ่ง − ระดับท้องน้ำ) × 100

| % ความจุลำน้ำ | สถานะ |
|---|---|
| > 100 หรือน้ำสูงกว่าตลิ่ง | 🔴 น้ำล้นตลิ่ง |
| 80–100 | 🟠 น้ำมาก |
| 30–80 | 🟢 น้ำปกติ |
| 10–30 | 🟡 น้ำน้อย |
| < 10 | 🟤 น้ำน้อยวิกฤต |
